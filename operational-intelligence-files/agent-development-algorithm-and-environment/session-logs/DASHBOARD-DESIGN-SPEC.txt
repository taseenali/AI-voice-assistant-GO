MEDVOICE AI RECEPTIONIST — DASHBOARD INTERFACE DESIGN SPECIFICATION
Pass 8 · May 2026
Purpose: Complete visual and interaction design for the Clinic Admin Dashboard.
This document describes what every pixel should do and why.
================================================================================


OVERVIEW
-------------------------------------------------------------------------------

Product:      MedVoice Admin Dashboard
Version:      1.0 (Clinic Admin)
Primary user: Clinic manager / practice administrator / front desk staff
Secondary:    Developer (for system health panel only)

What this dashboard is NOT:
  - Not a real-time call monitoring tool (no Twilio live yet)
  - Not a patient portal
  - Not a multi-tenant SaaS admin panel
  - Not a coding or developer tool (except the health/config panels)

What this dashboard IS:
  - The only place a clinic can see what Aria did today
  - The lead pipeline viewer for front desk staff
  - The safety audit log for emergency events
  - The system health check for whoever runs the server


================================================================================

DESIGN LANGUAGE
-------------------------------------------------------------------------------

Philosophy:
  Medical + modern tech. Trustworthy, clean, readable. Not flashy.
  A clinic manager should feel like they're using a professional medical tool,
  not a startup app. Data density is medium — not a wall of numbers.


Color Palette:

  Background (page):   #F1F5F9   (very light blue-gray — clinical, not harsh white)
  Sidebar background:  #0F172A   (deep navy — authority, stability)

PANEL 1 — OVERVIEW
-------------------------------------------------------------------------------

URL / nav state: Overview (default)
Page context: A summary of today's activity and recent sessions

HEADER
  "Good morning, MedVoice Clinic"  ← greeting changes by time of day
  "Thursday, May 7, 2026 · medvoice-clinic"  ← date + client

KPI CARDS ROW (4 cards, equal width, side by side)

  Card structure:
    Card label:  11px, uppercase, weight 600, color #64748B   ← top
    Card value:  32px, weight 700, color #0F172A              ← main number
    Card delta:  12px, weight 500                             ← trend vs yesterday
    Card icon:   right-aligned, 24x24, tinted to card theme

  Card 1 — TODAY'S SESSIONS
    Value: count of unique sessions today
    Delta: "+5 vs yesterday" (green if positive, red if negative)
    Icon: chat bubble
    No special color — neutral

  Card 2 — LEADS CAPTURED
    Value: count of leads with completeness > 0 today
    Delta: "avg completeness: 72%"
    Icon: person with checkmark
    Color: #10B981 accent on top border

  Card 3 — AVG ENGAGEMENT SCORE
    Value: float (e.g. "68.4")
    Sub: "12 high · 8 medium · 3 low"
    Icon: bar chart
    Color: amber if < 50, green if >= 65, neutral otherwise

  Card 4 — EMERGENCY ALERTS
    Value: count of emergency events today
    Sub: if > 0: "All received 911 redirect"
         if 0:   "No alerts today"
    Icon: warning triangle
    Color: entire card gets red tint (#FEF2F2 background) if value > 0
    Border: 1px solid #FCA5A5 if value > 0


MIDDLE ROW (two columns)

  LEFT — Recent Sessions Table (60% width)
    Title: "Recent Sessions"
    Subtitle: "Last 10 sessions · click any row to view transcript"

    Table headers (all uppercase 11px):
      TIME | SESSION | SERVICE | TURNS | ENGAGEMENT | LEAD | STATE

    Row contents:
      TIME:        relative ("2 min ago", "1 hr ago") — tooltip shows full timestamp
      SESSION:     first 12 chars of sessionId, monospace font, gray
      SERVICE:     colored pill badge with service name
      TURNS:       integer, centered
      ENGAGEMENT:  thin horizontal bar (0–100) + number beside it
                   color: green >=65, amber 40–64, red <40
      LEAD:        checkmark icon (#10B981) if lead captured, dash (#94A3B8) if not
      STATE:       colored text badge
                     CLOSING → green
                     ENDED → gray
                     FALLBACK → amber
                     OBJECTION → orange
                     LEAD_CAPTURE → blue

    Hover: row background #F8FAFC, cursor pointer
    Click: navigates to Sessions panel with that session pre-selected

    Footer: "View all sessions →" link to Sessions panel

  RIGHT — Service Distribution (40% width)
    Title: "Service Distribution"
    Subtitle: "Last 7 days · by intent detected"

    Donut chart:
      Segments: one per service + "Other" for unclassified
      Colors match service badge colors defined above
      Center: "47" (total) in large text, "sessions" small below
      Segment hover: tooltip shows count and percentage

    Legend below chart:
      Each item: colored dot + service name + count + percentage
      E.g.: [●] Dental · 15 · 32%


BOTTOM ROW — 7-Day Trend (full width)

  Title: "Sessions & Leads — Last 7 Days"

  Line chart:
    Two lines:
      Line 1: Sessions — #2563EB solid, 2px
      Line 2: Leads — #10B981 solid, 2px
    Both lines have dots at each data point
    Fill under each line: 15% opacity of line color
    X-axis: day labels ("Mon", "Tue", etc.)
    Y-axis: starts at 0, max = highest value + 20%
    Gridlines: horizontal only, #F1F5F9, very light
    Legend: top-right corner of chart

  If no data yet: empty state (see Empty States section below)

  Each card shows a shimmer animation (gray → lighter gray, cycling)

  5–8 skeleton rows with shimmer on each cell

WHAT MAKES THIS DASHBOARD MEDICALLY APPROPRIATE
-------------------------------------------------------------------------------

1. No patient PHI in the URL bar.
   All lead/session detail opens in slide-over panels or tab navigation.
   A URL like /leads/sarah-mitchell would expose PHI in browser history.

2. Completeness tracking instead of "missing data" alerts.
   Medical software should feel helpful, not accusatory.
   "75% complete" is better than "MISSING: dob, insurance_provider"
   (even though the data is the same — the framing matters).

3. Emergency log uses neutral reporting language.
   The log does not say "Patient may have been in danger."
   It says "911 redirect sent" — factual, not alarming.
   Clinic staff should not be re-alarmed by every row in the log.

4. No patient profile pages.
   This version does not build a persistent patient identity.
   Each lead is a session artifact, not a patient record.
   This is intentional — a patient record system requires a different
   regulatory framework (EHR integration, patient consent, etc.).

5. Config panel warns about editing.
   Prevents well-meaning staff from accidentally breaking the config
   through a UI before proper validation and write APIs are in place.

WHAT IS EXPLICITLY OUT OF SCOPE FOR VERSION 1
-------------------------------------------------------------------------------

These items were considered and rejected for v1. They should not creep in.

  - Patient login / patient portal
  - Real-time call audio monitoring
  - Multi-tenant client management
  - Role-based access control (admin vs. staff roles)
  - EHR / EMR integration (HL7, FHIR)
  - Billing or payment information
  - Appointment scheduling FROM the dashboard (dashboard reads, not acts)
  - Medication or clinical data of any kind
  - AI model training or fine-tuning interface
  - White-label customization UI
