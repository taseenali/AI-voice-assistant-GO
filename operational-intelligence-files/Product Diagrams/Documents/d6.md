# 🧩 MEMORY SYSTEM (WHAT IT REALLY IS)

---

## 🔹 1. SHORT-TERM MEMORY (WORKING MEMORY)

### Definition:

```text
Current conversation context
(last few turns, active info)
```

📌 Real concept:

> Working memory holds immediate context in a conversation thread ([Medium][2])

---

### Example:

```text
User: "I need a website"
→ memory: { problem: website }
```

---

## 🔹 2. LONG-TERM MEMORY (PERSISTENT MEMORY)

### Definition:

```text
Stored knowledge across sessions
```

---

### Types:

From real systems:

* **Semantic memory** → facts (user business, preferences)
* **Episodic memory** → past conversations
* **Procedural memory** → learned patterns ([MachineLearningMastery.com][3])

---

### Why needed:

> Without memory, conversations reset every time and feel broken ([Medium][4])

---

## 🔹 3. MEMORY STRUCTURE (ENGINEERING FORMAT)

You must store memory as:

```text
key
value
confidence
timestamp
```

---

### Example:

```json
{
  "key": "service",
  "value": "website",
  "confidence": 0.9,
  "turn_acquired": 2
}
```

---

# ⚠️ CRITICAL MEMORY PRINCIPLES

---

## ✅ 1. NOT EVERYTHING SHOULD BE STORED

From best practices:

> Only store relevant and useful data, filter aggressively ([LinkedIn][5])

---

## ✅ 2. MEMORY MUST EVOLVE

Users change.

System must:

* overwrite outdated data
* track recency

---

## ✅ 3. MEMORY ≠ CHAT HISTORY

Bad:

```text
Store entire conversation
```

Good:

```text
Store structured facts
```

📌 Real issue:

> Storing raw history is inefficient and expensive ([DEV Community][6])

---

# 🧠 STATE MACHINE (CONTROL SYSTEM)

---

## 🎯 Role:

> Control “where the conversation is”

---

## 🔹 Example States

```text
FLOW_DISCOVERY
FLOW_QUALIFICATION
FLOW_CLOSING
FLOW_GENERAL
```

---

## 🔹 What it does:

```text
Current State + Input → Next State
```

---

## 📌 Industry truth:

Dialogue systems require **state tracking to manage conversation flow** ([Hugging Face][7])

---

# 🧠 SESSION CONTEXT (THE GLUE)

---

## 🎯 What it stores:

```text
session_id
active_state
tone_state
interrupt_flags
deferred_intents
```

---

## 🔹 Why needed:

* isolate users
* track conversation lifecycle
* prevent cross-session leakage

---

📌 Real challenge:

> Multi-user systems must isolate sessions properly ([DEV Community][6])

---
