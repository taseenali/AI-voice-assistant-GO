\chapter*{Executive Summary}
\addcontentsline{toc}{chapter}{Executive Summary}

MedVoice AI is a multi-tenant medical receptionist platform. The \textbf{product layer} (tenant config, calendar logic, lead capture, dashboards, billing) is yours. The \textbf{runtime layer} (real-time audio, STT, TTS, turn-taking) should be delegated to \textbf{Vapi} for fastest path to revenue.

\textbf{Two integration wires:} (1) assistant-request config at call start; (2) tool-calls + end-of-call-report during/after calls.

\textbf{Current state:} Web widget functional; phone scaffolded; Vapi not integrated; HIPAA not implemented.

\textbf{Recommended path:} L1 Phone MVP in 2 weeks $\rightarrow$ L2 first paying client in 6 weeks at \$1,500--2,500/mo.

\chapter{Vapi Integration Guide}

\section{What Changes vs.\ What Stays}
Full detail in standalone \texttt{01-vapi-integration.pdf}.

\subsection{Drop}
Browser phone orchestration, \texttt{voice.js} WebSocket scaffold, real-time media ownership.

\subsection{Keep}
\texttt{configs/}, calendar routes, leads, emergency, dashboard, SQLite, webhook pattern.

\subsection{Build New}
\texttt{server/routes/vapi.js} with \texttt{assistant-request}, \texttt{tool-calls}, \texttt{end-of-call-report} handlers.

\subsection{Implementation Checklist}
\begin{enumerate}
  \item Vapi account + BYOK keys (Deepgram, OpenAI, ElevenLabs)
  \item Twilio number imported to Vapi
  \item Three webhook endpoints on MedVoice backend
  \item Four Vapi tools mapped to existing calendar/lead APIs
  \item Phone number $\rightarrow$ tenant mapping for multi-tenancy
  \item Server-side webhook worker (replace browser outbox for phone)
  \item E2E test: call $\rightarrow$ book $\rightarrow$ transcript in dashboard
\end{enumerate}
